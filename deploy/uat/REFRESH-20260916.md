## Isolation and incident resolution

The UAT DB hit its 512 MiB cgroup memory limit while provisioning copied users
after import. The first automatic rollback attempt could not connect while MariaDB
was restarting. UAT stayed stopped. After verifying available host memory, only
the UAT DB cap was raised to 768 MiB; user provisioning was completed atomically,
the UAT schema rebuilt and the full comparisons above passed. The refresh helper
now requires this cap and waits for DB recovery before rollback. These helper
improvements were syntax-checked; the complete revised helper was not rerun over
the verified baseline. Production containers/resources were unchanged.

Final checks confirmed separate application mounts, grants only on `crm_uat`,
internal UAT networks and blocked UAT connections to production DB addresses,
the public DB port and external HTTPS. Mail/cron/integrations/webhooks remain off.
Both https://crm.thnglobal.vn and https://crm-uat.thnglobal.vn return HTTP 200.

No production application, database, user, password or role was modified.
